# Capability evaluation

Evaluate existing capabilities before implementing a new skill, template, or
workflow. Start with the capability required rather than a preferred product.

For each candidate, record provenance, licence, maintained version, supported
agents, configuration model, external data flow, side effects, lifecycle fit,
project-overlay support, upgrade path, and gaps.

Prefer, in order:

1. adopt without modification;
2. configure through supported extension points;
3. wrap with a narrow compatibility layer;
4. replace for a recorded material reason;
5. build when no suitable maintained capability exists.

The initial evaluation backlog includes requirements discovery, specification,
planning, task decomposition, consistency analysis, code review, security review,
accessibility review, evidence assembly, and release observation. GitHub Spec Kit
is the initial candidate for specification, planning, tasks, and cross-artefact
analysis; adoption is not assumed until a pilot establishes fit.
