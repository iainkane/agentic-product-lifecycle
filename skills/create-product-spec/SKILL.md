# Create a product specification

Use the accepted intent and reviewed requirements as sources. Include scope,
non-goals, user scenarios, numbered requirements, acceptance scenarios, assumptions,
open decisions, dependencies, success measures, and required project reviews.

Maintain traceability rather than duplicating contradictory text. Keep technical
design out of the product specification unless it is an agreed constraint. Surface
unresolved blocking questions and do not mark the specification approved without
an attributable product decision.

If an adopting project uses an established specification framework such as Spec
Kit, use its supported templates or extension points and retain lifecycle IDs.
